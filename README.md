# Прототипы Test AI

Как собрать кликабельный прототип экрана, чтобы проверить и показать решение до разработки.

Прототип это не дизайн-макет и не документация для разработчика. Это быстрый способ увидеть и пощупать решение. Он выглядит как настоящий продукт, потому что собран из его настоящих частей. В прод не идёт.

## Как запустить

Скинь этот репозиторий Клоду (Claude Code), он развернёт его локально. Дальше просто говори: «собери прототип по <ссылка на сценарий или задачу>». Агент сам подтянет всё нужное.

## Сначала сформулируй решение

Прототип собирается по сценарию, а сценарий пишется по PRD. Чем понятнее сценарий, тем точнее прототип.

- Навык `create-prd` поможет сформулировать и обновлять PRD.
- Навык `create-scenario` соберёт сценарий, если его ещё нет.

## Как поставить задание

Коротко опиши вводную:

- Опирайся на сценарий или PRD: дай ссылку, не пересказывай контекст. Последовательность шагов и состояния берутся оттуда, описывай вручную только если их нет.
- Назови целевой сценарий и стартовый экран.
- Задай скоуп: что показать, например только основные сценарии без корнер-кейсов.
- Дай реальные данные или скажи, какие подставить.
- Редизайн: скажи, что меняется в самом экране, а не «оболочка поверх старого».

## Как посмотреть и показать

- Пока работаешь: агент будет поднимать результат локально в браузере.
- Для демонстрации: агент опубликует в Vercel и даст ссылку. Аналоги: Cloudflare Pages, Netlify.

## Ограничения прототипа

- Только десктоп, широкий экран.
- Данные ненастоящие, вписаны прямо в прототип. Если нужно, укажи, какие данные подставить.
- Нет бэкенда, авторизации и сохранения.
- Не финальный дизайн до пикселя.
